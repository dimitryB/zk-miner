# HemiProve ABIs

Generated by `scripts/gen-abi.sh` from deploy-profile (`FOUNDRY_PROFILE=deploy`) build artifacts; CI runs `scripts/gen-abi.sh --check`, so every file here matches the commit it ships with. What changed and when: `CHANGELOG_ABI.md`.

## Deployed addresses

This directory publishes ABIs, not addresses.

- **Hemi testnet (743111).** Every stack deployed before the new deployment is **abandoned**, including all eight BatchCycleCommittee proxies. Do not use them. The 743111 broadcast logs that exist today (`DeployTestnet.s.sol`, `DeployViaFactory.s.sol`, `DeployProgramRegistry.s.sol` and the demo scripts) all belong to those abandoned stacks.
  - The new deployment is the mainnet dress rehearsal (`DEPLOY_RUNBOOK.md`, "Fresh deploy"). Its addresses are **TBD until that rehearsal completes**.
  - They will then be in the "New deployment" rows of `../deployment-hemi-testnet.csv`, the one integrator-facing record for 743111.
- **Hemi mainnet (43111).** Not deployed yet. It will follow the same procedure.

What changed for integrators since any earlier stack: `CHANGELOG_ABI.md`.

## What "the router" means

`HemiProve` is a diamond-lite router at a single stable address. It holds all storage and `delegatecall`s to 5 facet impls based on selector. You **always** send transactions to the router address — never to a facet impl. The merged `HemiProveRouter.abi.json` is what your web3 client should attach to that address.
